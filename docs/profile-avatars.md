# Profile avatars

Signed-in viewers can open Account → Change avatar, choose one of ten characters, preview it, and save. The selection appears on the account profile, desktop account link and mobile Account tab. The picker and messages support English and Arabic. Initials remain the default for ordinary accounts. Admins and the verified site developer receive their signature portrait automatically when no avatar is saved. Existing saved choices are preserved, and everyone can choose initials from the picker.

The ten stable IDs are orbit (astronaut), nova (robot), ember (fox), luna (cat), storm (wolf), jade (dragon), echo (owl), pixel (gamer), sol (lion), and vela (alien). They share an original AI-generated five-column/two-row atlas exported as a 339 KB WebP. CSS positions display each square without changing the original character artwork. The browser can reuse the same asset for the picker and navigation; no external image service or per-request image generation is required.

Admins also have an eleventh, exclusive choice: `sovereign`, a purple lion guardian with a gold crown, stored in `/avatars/admin-sovereign.webp`. It is the automatic default when an admin has no saved choice, and can also be selected under Account → Change avatar and uses the same profile and navigation surfaces. English and Arabic labels identify the admin choice. Its original generated artwork is exported as a 302 KB WebP. No schema change is required.

Only the ten standard IDs, the initials reset, or the exclusive portraits allowed by the authenticated account identity are accepted by the server action. The server uses the current database role and ignores any submitted role. The picker hides the exclusive choice from viewers, and all profile/navigation renders fall back to initials if a former admin still has that saved ID. It authenticates the session and updates that account alone; external URLs and other users' IDs are not accepted as avatar sources or update targets. `User.avatarId` is nullable, so missing/unknown choices fall back to initials.

The additive update `prisma/updates/20261025-profile-avatars.sql` adds the nullable field without changing current profiles. Vercel production preparation applies the explicit security/library and avatar updates, each transactionally and repeatably. Preview builds continue to skip database changes and need an upgraded preview database for authenticated testing. Outside Vercel, run `npm run db:upgrade` before publishing.

Validation: 39 tests passed, including admin-only selection, forged-role rejection, role removal and Arabic admin labels, alongside all ten standard choices, account ownership, invalid identifiers, initials restoration, picker preview/localization and migration repeatability. Type checking, lint (existing warnings) and production build passed. Local HTTP testing submitted the real progressive form, verified persistence after reload and avatar rendering in account/navigation, rejected an arbitrary URL, verified demotion hides the exclusive artwork and blocks saving it, restored initials, checked Arabic/RTL and fetched the generated WebP. Browser visual review was unavailable; the generated artwork itself was visually inspected.


## Distinguished team identities

The account profile has a gold royal treatment for admins and a cyan/violet creator treatment for the site developer, with localized role badges, larger portraits, signature frames, a dedicated team panel and corresponding desktop/mobile account markers. Frames and badges remain visible when choosing a standard avatar or initials. These are cosmetic identities; existing admin permissions and subscription/access rules are unchanged.

`getAccountIdentity` resolves identity on the server from the authenticated database row. The exact designated developer email is `mobanunir@gmail.com`, matched case-insensitively after trimming and only when `emailVerified` is set. Unverified accounts and lookalike/plus addresses do not receive the developer identity. A developer who already has the ADMIN role keeps those existing permissions; this feature grants none. Only the resolved identity and role are passed to client components, not the designation email.

The developer-exclusive `architect` portrait is an original cyan/platinum futuristic owl at `/avatars/developer-architect.webp` (267 KB WebP). It is the developer's default when no choice is saved. No user row, verification state, role, subscription, or schema is changed to enable identities. The feature also takes effect if the owner creates/verifies the designated account later. Special accounts store the explicit `initials` sentinel when resetting so it overrides the signature default; ordinary accounts continue to store null for initials.

Tests cover exact verified email matching, developer/admin/ordinary presentation, default portraits, custom-avatar frames, initials, exclusive selections, forged identity/email fields, revoked verification and unchanged admin/paid access. Local HTTP checks verify the rendered profile, navigation, real form saves, Arabic/RTL and asset delivery; no real production accounts are used for testing.
